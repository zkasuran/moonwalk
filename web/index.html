MoonWalk

USDC nanopayment rails for agent commerce, live on Arc mainnet (chain 5042). reading the chain...

An agent that charges per call cannot settle each $0.001 call on-chain, because the fee costs more than the call. MoonWalk fixes that with a payment channel. The payer funds once by signing an authorization and never sends a transaction again. It signs one cumulative voucher per call. The service redeems a whole batch in a single transfer. On top of that, each person in a shared channel has a spend cap enforced by a contract, so one agent wallet serves many humans and nobody can be overspent, the operator included.

Why Arc: gas is USDC itself, so the fee and the payment are the same asset and the fee-to-value ratio is fixed at design time. Arc has single-block finality, so a channel close is final in one block with no confirmation counting and no reorg to handle. Everything below is read live from the public Arc RPC in your browser. Nothing here needs a wallet or any funds.

Bob has spent his cap. The next $0.001 voucher for bob would take him over it, so SpendGuard.consume reverts CapExceeded and the redeem cannot settle it. This is a contract rule, not a server promise.
